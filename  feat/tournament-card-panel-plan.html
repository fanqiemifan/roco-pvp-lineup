系列赛卡片 · 右键菜单 + 复用「当前比赛」面板 在「系列比赛」视图内直接完成某场对决的操作 · headless 登记（不切换当前比赛）· 右侧 Drawer 复用赛事面板 · 洛克王国赛事推流控制台

① 问题与目标

现状：登记一场要跳四次

现在 晋级图看对阵→ 点「进入管理」→ 切当前比赛 + 跳到赛事面板→ 开始 / 登记胜负→ 跳回系列赛找下一场

跳转丢上下文：晋级图的选中链路、滚动位置、正在看的那一波。连续登记同一波多场时最烦。

目标：右键就地操作

目标 右键卡片 / 点「⋯」→ 菜单直达：左赢 / 右赢 / 开始 / 撤回→ 或打开 Drawer 做完整操作

动作默认 headless：只写目标那场比赛，不切换当前比赛，因而不打断正在推流的那一场画面。

② 关键结论：能不能不切换当前比赛就登记？

能。服务端本来就是按 matchId 工作的：startCurrentGame / recordMatchWinner / undoMatchAction 都接受任意 matchId，只写那一场；内部的面板/记分牌同步只作用于「当前比赛」，对非当前比赛是空操作——既不污染它，也不把它推上画面。
操作接口需切换当前比赛？副作用 / 说明
开始本次对局POST /api/matches/:id/start 不需要 只该场小局转 in_progress；要求该场「当前小局」双方阵容已录
左赢 / 右赢POST /api/matches/:id/winner 不需要 写该场比分；完成时跑系列赛写回钩子推进晋级图（tournament:update）
撤回 / 取消撤回POST /api/matches/:id/undo|redo 不需要 撤回栈按比赛存（flowHistory[matchId]）；撤回还会回退节点、必要时级联丢弃「自动锁定且未开打」的后续波
录入阵容POST /api/matches/:id/games/:n/lineup 不需要 只写比赛记录、不动推流画面（门槛：该局是当前小局且未开始）
保存排位排名 / 战队PATCH /api/matches/:id 不需要 纯展示字段；选手名与赛制已由系列赛锁定，不在此改
实时面板阵容编辑PATCH /api/panels/:side 需要 编辑的就是「当前比赛」的推流面板（全局面板 + 600ms 防抖自动保存）
头像上传 / 删除POST /api/upload/avatar/:side
DELETE /api/delete/avatar/:side		 需要 接口硬绑 activeMatchId（赛事覆盖头像目录按它拼路径）
胜者结算上屏（page10）— 需要 page10 内容取当前比赛；不切换时不应触发，否则播出的是别的一场
必须修的一处（唯一的真障碍）
winner 路由末尾无条件调用 triggerWinnerStage()：只要当前画面是 page1-3 就切到 page10，而 page10 的内容取 findActiveMatch → headless 登记会把别人的比赛播上屏。
修法：matchId === activeMatchId 时才触发（约 3 行）。

① 赛事面板内联（variant=inline）

抽取要点

  • matchForm 移进组件内部并按 match.id 回填 → 消除双挂载的表单争用
  • 阵容编辑器用 插槽 传入（rosterEditor?: ReactNode），只在本场=当前比赛时注入，避免 18 个 prop 再透传一遍
  • 进度条 / 系列赛锁字段判定在组件内算
  • 动作以 onAction(matchId, action, extra?) 回传，组件不打接口

为什么不会双挂载冲突

  • 赛事面板（view==='roster'）与系列比赛（view==='tournament'）是互斥渲染
  • Drawer 只在系列赛视图、open 时挂载并 destroyOnHidden
  • 全局面板 600ms 防抖挂在 Dashboard 层（不随编辑器卸载而丢），同一时刻只有一个编辑器 → 不会争用同一份 panels

⑤ 撤回可用性：提前置灰（不靠报错发现）

撤回功能在 headless 下完整可用（撤回栈与接口都按比赛），差的是「按钮能否预判」。读模型里的 undo.canUndo 只算当前比赛，因此给它补一份按比赛摘要：

// MatchStoreState.undo { canUndo: true, // 当前比赛（保持原样，赛事面板继续用） canRedo: false, canUndoDelete: true, deleteUndoCount: 2, byMatch: { // 新增：只收有栈的场次（每场两个布尔，增量可忽略） "20260928_A001": { canUndo: true, canRedo: false }, "20260928_A002": { canUndo: false, canRedo: true } } }

为什么不用新接口

  • 服务端每次写都会回带并广播整份 store → 菜单与 Drawer 的按钮状态自动最新
  • 不需要在「菜单打开 / 切场 / 每次动作后」补拉取与刷新，少一类陈旧态 bug
  • 只透布尔，不把带 7 天 TTL 快照体的 flowHistory 原样透出

消费方式

  • Drawer / 菜单：undo.byMatch[matchId] ?? {canUndo:false, canRedo:false}
  • 赛事面板那对按钮不变（仍走 undo.canUndo）
  • 缺省 = 两个按钮都置灰（比「可点但报错」更诚实）

⑩ 本次不做（刻意留白）

头像 headless

接口全绑 activeMatchId，要加 matchId 参数改造面不小；头像本就是低频操作，切一次当前比赛即可。

实时面板 headless

RosterPanelEditor 编辑的就是当前比赛的推流面板，18 个 prop 也不适合再参数化；headless 的阵容录入走「录入阵容」通道（已有现成弹窗）。

危险动作进菜单

删除对局 / 回退上一波 / 删除系列赛不进右键菜单——低频且破坏性强，留在系列赛工具栏的确认弹窗里。

多选批量登记

这次只做单场操作；一波批量登记等右键菜单落地后按需再加。
