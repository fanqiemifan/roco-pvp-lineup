# 系列赛卡片：右键菜单 + 复用「当前比赛」面板（Drawer）

## Context

裁判在「系列比赛」视图里看晋级图/波次列表时，要登记一场胜负必须先点「进入管理」→ 切换当前比赛 → 跳到「赛事面板」→ 操作完再跳回来。跳转丢上下文（晋级图选中链路、滚动位置），连续登记一波多场时尤其烦。

目标：在系列赛视图里直接完成某场对决的操作，不离开当前视图。

已拍板的形态：
- 卡片上 **右键菜单 + 卡片「⋯」按钮**（共用同一份菜单），菜单含高频动作直达。
- 「赛事面板 → 当前比赛」那张面板抽成可复用组件，在**右侧 Drawer** 里复用。
- 高频动作（开始本次对局 / 左赢 / 右赢 / 撤回）**默认不切换当前比赛**（headless 登记）；切换当前比赛是显式动作。

## 关键前提（已核实）

服务端本来就按 matchId 工作，headless 基本现成：

- `startCurrentGame(paths, matchId)`（[match-service.ts](file:///d:/GitHub/roco-pvp-webui/electron/services/match-service.ts#L1701-L1735)）：任意 matchId，只要求**该场**当前小局双方阵容已录，只写该场记录。
- `recordMatchWinner(paths, matchId, winner)`（[match-service.ts](file:///d:/GitHub/roco-pvp-webui/electron/services/match-service.ts#L1737-L1783)）：同上，只要求该场有 in_progress 小局。
- 两者内部 `syncAfterStoreChange`（[L1050-1058](file:///d:/GitHub/roco-pvp-webui/electron/services/match-service.ts#L1050-L1058)）只把**当前比赛**同步到面板/记分牌 → 对非当前比赛是空操作（不污染它、也不把它推上画面）。
- `/undo` 与 flowHistory 也是按 matchId 的。
- 云同步闸门 `cloudRegisterGate/cloudUndoGate(matchId)`（[App.tsx](file:///d:/GitHub/roco-pvp-webui/src/admin-antd/App.tsx#L4240-L4270)）已按 matchId —— 新入口必须复用，否则分控端能绕过「未指派不可登记」。

**唯一硬障碍**：winner 路由末尾无条件调 `triggerWinnerStage()`（[socket-server.ts](file:///d:/GitHub/roco-pvp-webui/electron/socket-server.ts#L1448-L1475) → [L462-484](file:///d:/GitHub/roco-pvp-webui/electron/socket-server.ts#L462-L484)），而 page10 内容取 `findActiveMatch`（[/api/page10](file:///d:/GitHub/roco-pvp-webui/electron/socket-server.ts#L778-L783)）→ headless 登记会把**别的**比赛播上屏。必须加守卫。

撤回的可用性（已定：**必须提前置灰**）：

- 撤回栈按比赛存（`store.flowHistory[matchId]`，[L798-805](file:///d:/GitHub/roco-pvp-webui/electron/services/match-service.ts#L798-L805)），`/undo|/redo` 也按 matchId → headless 撤回**功能完整**。
- 但读模型的 `undo.canUndo/canRedo` 只算当前比赛（[toPublicStore:821-834](file:///d:/GitHub/roco-pvp-webui/electron/services/match-service.ts#L821-L834)）→ 非当前比赛的面板/菜单判不了按钮状态。**做法**：给 `MatchStoreState.undo` 增加一份按比赛摘要 `byMatch: Record<matchId, {canUndo, canRedo}>`（只收 undoStack/redoStack 非空的场次）。比"新开一个 `GET /api/matches/:id/undo-state` 接口"更省：无需在菜单打开/切场/每次动作后补拉取与刷新，store 每次写都会广播，状态天然最新；`/api/matches` 增量只是每场两个布尔。

保留的缺口（本次接受，见「不做」）：
- 头像（`GET /api/avatars`、上传/删除）硬绑 activeMatchId。
- 实时面板阵容编辑（`RosterPanelEditor` → `/api/panels/:side`）本质作用于当前比赛。

## 设计

### 1. 组件拆分

新增 `src/admin-antd/components/CurrentMatchPanel.tsx`，把 [App.tsx 4749-4956](file:///d:/GitHub/roco-pvp-webui/src/admin-antd/App.tsx#L4749-L4956) 的卡片抽出来。

- **以目标 match 为参数**（`match: MatchRecord`），不再读全局 `activeMatch`；`currentGame`、`progress`（`buildProgressItems`）、`lineupLocked`、系列赛字段锁定判定都在组件内算。
- **`matchForm` 移入组件内部**（`Form.useForm` + 按 `match.id` 回填 effect），删除 Dashboard 的 `matchForm`（608）与回填 effect（1042-1055）——消除双挂载时的表单争用。已确认 `matchForm` 只被卡片与其回填 effect 使用。
- 动作以 `onAction(matchId, action, extra?)` 形式回传，不在组件内直接打接口。
- **阵容编辑器用插槽传**：`rosterEditor?: ReactNode`（只有目标=当前比赛时由 App 注入 `<RosterPanelEditor/>`），避免把 18 个 prop 再透传一遍。
- 新增 `variant: 'inline' | 'drawer'` 控制布局差异（Drawer 内需要紧凑单列）。
- `statusBar?: ReactNode` 插槽：Drawer 里放「本场是否当前比赛」状态条。

双挂载：赛事面板（`view==='roster'`，4683-4990）与系列比赛（7025-7036）互斥渲染；Drawer 只在系列比赛视图、`open` 时挂载并 `destroyOnHidden`。因此任意时刻只有一个 `RosterPanelEditor`，Dashboard 层的全局 600ms 防抖（[1188-1207](file:///d:/GitHub/roco-pvp-webui/src/admin-antd/App.tsx#L1188-L1207)）不会被两处争用（防抖在 Dashboard、不随编辑器卸载而丢）。

### 2. Drawer

- 挂在 App 层（`open` 时渲染），`mask={false}` 让晋级图仍可点：点另一张卡片即切换 Drawer 的**目标比赛**（这就是「连续登记」的关键）。
- 顶部状态条两种形态：
  - 目标是当前比赛 → 「本场为当前比赛（推流画面同步）」，注入 `rosterEditor`（可改实时面板阵容、可改头像）。
  - 目标不是当前比赛 → 「本场未设为当前比赛 · 当前推流：X vs Y」+ 按钮「设为当前比赛」；实时面板编辑与头像在该状态下不注入/禁用；阵容改走「录入阵容」（复用 `HistoryLineupEntryModal`，写比赛记录不动画面）。
- 「设为当前比赛」复用现有 `selectMatch`（[1455-1492](file:///d:/GitHub/roco-pvp-webui/src/admin-antd/App.tsx#L1455-L1492)，含确认弹窗与「不再提示」记忆），但**不跳转视图**。
- 撤回/取消撤回照常提供（headless 也支持系列赛反向钩子与云闸门）；按钮状态取 `undo.byMatch[matchId]`（缺省 = 两个按钮都置灰），与「赛事面板」那对按钮同一份数据，只是按目标比赛取值。

### 3. 卡片菜单

`components/TournamentNodeCard.tsx`：`Dropdown(trigger={['contextMenu']})`，并加「⋯」按钮打开同一份菜单（管理端没有右键先例，只靠右键用户找不到）。

- 菜单项：打开比赛面板 / 左赢 / 右赢 / 开始本次对局 / 撤回上一步 / 查看阵容 / 弃权判负 / 进入管理。
- 可用性判据由父级算好传入（`BracketCard` 不含 `games`，见 [lib/tournament.ts](file:///d:/GitHub/roco-pvp-webui/src/admin-antd/lib/tournament.ts#L422-L434)）：`isCurrent`、`canStart`（未完赛 + 有 pending 局且有双方阵容）、`canRegister`（有 in_progress 局）、`canUndo/canRedo`（取 `undo.byMatch[matchId]`，与 Drawer 同源）、以及云闸门的 `{allowed, reason}`。
- 新增 `TournamentViewProps`：`activeMatchId`、`onMatchAction`、`onSetCurrent`、`onOpenMatchPanel`、`onOpenLineupEntry`、`registerGate`、`undoGate`；经详情组件 → BracketBoard（[475-485](file:///d:/GitHub/roco-pvp-webui/src/admin-antd/components/BracketBoard.tsx#L475-L485)）与波次列表（[TournamentView 1477](file:///d:/GitHub/roco-pvp-webui/src/admin-antd/views/TournamentView.tsx#L1477)）透传到卡片。
- DOM 风险：Dropbox cloneElement 会不会覆盖 `cardRef`？首选「Dropdown 包住卡片根 div」，**实施第一步先实测晋级图连线是否仍对齐**；若被覆盖，回退为「根 div 上 `onContextMenu` + 受控 Dropdown（锚在 ⋯ 按钮）」，零 DOM 改动。

### 4. 动作层

- `runMatchAction(matchId, action, extra?)`（现写死 `activeMatch.id`，[2281](file:///d:/GitHub/roco-pvp-webui/src/admin-antd/App.tsx#L2281-L2293)）；成功后文案取目标 match，headless 时明确追加「推流画面未切换，如需上屏请点『设为当前比赛』」。
- `doSelectMatch(matchId, { navigate })`：Drawer 用 `navigate:false`（不 `setView('roster')`），其余行为（拉头像、notice）不变，赛事面板调用点传 `true` 行为不变。
- 所有新入口先过 `cloudRegisterGate/cloudUndoGate`，不允许则置灰 + tooltip 显示 reason。
- 撤回/登记后不需要额外的状态刷新：服务端每次写都会回带并广播整份 store，`undo.byMatch` 随之更新，菜单与 Drawer 的按钮状态自动跟上。

### 5. 服务端（很小）

- winner 路由：`matchId === getMatchStore(paths).activeMatchId` 时才 `triggerWinnerStage()`；否则只更新赛果与晋级图。
- `MatchStoreState.undo` 增加 `byMatch`（[shared/types.ts:124-133](file:///d:/GitHub/roco-pvp-webui/shared/types.ts#L124-L133) 类型 + [toPublicStore](file:///d:/GitHub/roco-pvp-webui/electron/services/match-service.ts#L821-L834) 组装），语义写进 `.agents/05`。已确认现有测试只断言 `undo.canUndo` 单字段、无整对象相等断言，新增字段是加性改动。
- 本次不加头像 matchId 参数。

## 回归风险

- `tests/admin-antd/hooks-order.test.ts`：新 state 必须是 Dashboard 组件级（缩进 2）且位于 `if (loading)` 早退之前，否则测试红/白屏（React #310）。
- 赛事面板行为必须零变化（同一组件两处复用，任何 props 形状变化都要两边都过一遍）。
- 全局面板 600ms 防抖 + `pendingDraftRef` 草稿上下文：确保同一时刻只有一个编辑器（Drawer 与 roster 视图互斥）。
- CSS：`current-match-*` 依赖 `.roster-overview-row/col`，三列 grid 的收列断点是**视口**（992px），Drawer 内需 `variant='drawer'` 覆盖为紧凑列布局，否则横向溢出。
- BracketBoard 连线量测（`cardRef`/`slotRef`）与左键拖拽：右键不触发拖拽（仅 `button===0`），但要确认 Dropdown 未吞掉左键 click 与 ref。
- `MatchStoreState.undo` 形状变化：前端消费点（赛事面板那对按钮）与测试断言都要过一遍；`byMatch` 只收有栈的场次，别把 `flowHistory` 原样透出（含 7 天 TTL 的快照体，体积大）。
- 撤回后要连带刷新刚被回滚的晋级状态：`onMatchUndo` 已经会广播 `tournament:update`，不需要前端补逻辑，但手工验证时要覆盖「headless 撤回 → 晋级图回退」。
- 不做 UI 组件测试（项目无 jsdom/RTL）：可测逻辑尽量下沉到 `lib/`。
